# Abstract (ร่าง 2026-09-17)

การสร้างแบบจำลอง 3 มิติของห้องจากสมาร์ตโฟนพึ่งพาเซ็นเซอร์ LiDAR ซึ่งมีในเครื่องส่วนน้อย ทางเลือกคือโมเดล monocular depth ที่ก้าวหน้ามากในภาพเดี่ยว
แต่ยังไม่มีตัวเลขว่าเมื่อนำมาใช้แทน LiDAR ใน pipeline การสร้างห้องจริง ห้องที่ได้จะคลาดเคลื่อนกี่เซนติเมตร งานนี้เป็น system development ที่สร้าง pipeline
depth → scale alignment → TSDF fusion → mesh โดยให้ **แหล่ง depth และวิธีหา scale เป็น interface ที่สลับได้จาก config** แล้ววัดเรขาคณิตของ mesh
เทียบกับ reference จาก laser scanner บนห้องจริง 6 ห้องของ ARKitScenes (2,352 เฟรม) ภายใต้ pipeline เดียวกัน

ผล: pipeline เสีย 2.1 ± 0.5 cm (Chamfer, voxel 4 cm); LiDAR ของ iPad Pro เสียเพิ่มอีก 1.0 ± 0.3 cm (F@5cm 0.93); Depth Anything V2 ที่รู้ scale ทุกเฟรม
เสีย 6.5 ± 2.4 cm (F@5cm 0.74) — ห่างจาก LiDAR 3.4 cm; แต่เมื่อ calibrate scale เพียงครั้งเดียวต่อฉาก error กระโดดเป็น 22.7 ± 2.6 cm (F@5cm 0.22)
และโมเดล metric ที่ไม่ calibrate ให้ 49 cm การวิเคราะห์ต่อเฟรมแสดงว่าสาเหตุคือ scale ของโมเดลแกว่งหลายเท่าตามเนื้อหาของแต่ละมุมมอง ไม่ใช่ drift ตามเวลา
การ fit scale ต่อเฟรมด้วยจุด metric แบบ sparse เพียง ~200 จุด — ชนิดที่ VIO ของโทรศัพท์ให้ฟรี — กู้กลับมาได้ 7.2 ± 2.9 cm (F@5cm 0.69) ห่างจาก oracle เพียง 0.8 cm
ขนาดโมเดล (Large → Small) มีผลเพียง 2.8 cm ที่เวลาเร็วขึ้น 7× และจำนวนเฟรมกำหนด coverage ไม่ใช่ accuracy (ต้อง ≥ 0.8 fps)
ข้อสรุปสำหรับผลิตภัณฑ์: ช่องว่างระหว่างเครื่องมี/ไม่มี LiDAR อยู่ที่ปัญหา scale ต่อเฟรม ซึ่งแก้ได้ด้วยข้อมูล metric จาก VIO ไม่ใช่ด้วยโมเดลที่ใหญ่ขึ้น (และ confidence map ของ LiDAR ไม่ช่วยลด error ของ LiDAR เอง)
โค้ด, config ของทุกการทดลอง และ metrics ของทุก run เปิดเผยเพื่อทำซ้ำได้
