\begin{abstract}
Devices without LiDAR can reconstruct a room from monocular depth, but an off-the-shelf ``metric'' model such as Depth
Anything~V2 Metric-Indoor, trained on synthetic images, misplaces a real room by \SI{\rsMETRICCM}{cm} inside a
reconstruction pipeline. We ask whether \emph{transfer learning with depth from the phone's own LiDAR}---no laser scanner
involved---really makes this model better than its pretrained self \emph{when measured against a laser scanner}, the
Faro ground truth that ARKitScenes ships. We fine-tune only the DPT head (frozen encoder) on 24 ARKitScenes rooms with
labels from the iPad's LiDAR (R3) and compare it with the pretrained checkpoint through one depth $\rightarrow$ TSDF
$\rightarrow$ mesh pipeline in which the depth source is the single variable switched from a config file, on rooms never
used for training or checkpoint selection: six rooms with a Faro reference mesh (3D and 2D) and \rsVN{} further rooms
from the Validation fold (per-frame 2D against Faro depth, \rsVFRAMES{} frames).
R3 lowers Chamfer from \SI{\rsMETRICCM}{cm} to \SI{\rsFTLIDARALLCM}{cm} ($\rsMAINGAIN\times$, better in every room),
raises \fscore{} from \rsMETRICF{} to \rsFTLIDARALLF{} and lowers per-frame AbsRel from \rsMETRICSIXABSREL{} to
\rsFTLIDARALLABSREL; on the \rsVN{} unseen rooms AbsRel falls from \rsVMETRICABSREL{} to \rsVFTALLABSREL{} (better in
\rsVWINS/\rsVN)---all without calibration or any sensor at run time. A laser teacher (\SI{\rsFTFAROCM}{cm}) is not
measurably better than the LiDAR teacher, and Depth Pro given the camera's true focal length, without fine-tuning,
reaches \SI{\rsDEPTHPROCM}{cm}. The same pipeline gives the context: it loses \SI{\rsGTCM}{cm} on its own, iPad LiDAR
\SI{\rsLIDARCM}{cm}, a monocular model with the correct scale per frame \SI{\rsORACLECM}{cm}, and a per-frame fit on
$\sim$200 sparse metric points \SI{\rsSPARSECM}{cm}. Per-frame analysis shows R3's remaining error is a scale that
swings with the content of each view, which fine-tuning de-biases but does not remove. Supervision that used to need a
laser scanner can thus be collected with a consumer depth sensor and used to train a model that needs no sensor at run
time (measured here on the same iPad camera); the resulting rooms ($\sim$\SI{16}{cm}) are a large step toward, but not
yet at, the accuracy a rough overview needs, let alone furniture placement. Code,
every experiment config, every run's metrics, checkpoints and the room split are released.
\end{abstract}
